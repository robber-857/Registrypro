# Registrypro ASIC Assistant

这是本机 Registrypro 的 Chrome / Edge Manifest V3 扩展，不是商店已审核扩展。

## 安装与首次连接

1. 打开 `chrome://extensions`，开启开发者模式，点击“加载已解压的扩展程序”。
2. 选择本项目 `browser_extension` 文件夹（不要选择 ZIP 文件）。
3. 启动项目的 `start.cmd`，打开 `http://127.0.0.1:8765/`。
4. 展开“ASIC 浏览器插件”，点击“复制配对码”。打开插件弹窗粘贴配对码。
5. 选择名单与 5/15/30/60 秒间隔，点击“连接并开始”。插件创建一个专用 ASIC 标签页并依次查询。可以关闭弹窗，保持 Chrome 与本机服务运行。
6. 页面会显示队列进度，结果写回名单；重新下载 CSV 获取最新名称、日期与来源。

本机服务重启后配对码失效，需重新复制。插件暂停／继续保持当前队列；完全关闭 Chrome 或停止本机服务后重新连接并启动任务，已保存结果仍保留。系统中的“停止浏览器队列”用于结束旧队列，再新建名单任务。

## 读取与匹配规则

- 从本机名单建立任务，优先采用已发现的官方名称和编号，也对目录名称进行 ASIC Business Names 搜索。
- 在真实浏览器渲染的免费摘要中读取 Business Name、ABN、持有人、Principal place of business、Renewal date；公司摘要读取 ACN 和 Next review date。
- 名称必须与指定任务准确对应；服务端再次检查官方域名、ABN、ACN、登记状态，以及 ABN Lookup 当前名称。
- 新确认的门店要求登记商业名称／唯一对应主体名称与门店相符，且 **Principal place of business 的街道、门牌、单元与邮编一致**。缩写、州全称及楼层格式做有限规范化。同一 suburb/postcode、送达地址或公司注册办公室地区不等于门店营业地址。
- 已确认主体可按同一 ABN/ACN补上日期；不能因为查询到某候选日期，就把该日期填到未确认的门店上。
- ASIC 可能保留上一个查询页面。插件核对摘要名称，必要时改用页面内搜索；不会把上一个企业的日期写入下一家。
- 遇到同名多条、取消登记、地址不符、超时或验证码，保留原因，不任意选第一条。验证码须由用户自行处理，插件暂停且不绕过。
- 不选择付费报告、不加入购物车、不登录、不修改 ASIC 登记资料、不发送邮件。

## 权限与数据

仅申请 `storage`、`alarms`，以及 `connectonline.asic.gov.au`、`127.0.0.1` 的主机权限。运行代码只访问本机端口 8765 与 ASIC RegistrySearch 公共页面，不读取其他网站、浏览历史、密码或 Cookie。

配对码存储在 Chrome 会话存储中。摘要文本及判定依据保存至本机 `output/asic_browser_evidence/`，采纳的核验结果存于 `output/registration_browser.json`；它们不提交 GitHub。已人工核实／标注冲突的数据受保护。

## 验证范围

Python 回写与拒绝错误匹配的测试、JavaScript 语法检查已执行。真实浏览器已验证公司审核日期和 Business Name 续期日期页面。首次加载扩展后还需验证浏览器事件、动态表单与队列的完整联动，不能把单独浏览器研究称为扩展已完成端到端验收。
